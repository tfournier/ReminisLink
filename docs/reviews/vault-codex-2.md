## Bloquant

- **La rotation efface encore des données utilisateur sans sauvegarde.** Ouvrir le coffre ne déclenche plus de rotation. À la publication suivante, la rotation s’applique toutefois à toute l’union et supprime récursivement les versions hors limite. Dans le scénario du test, publier une 15e version efface cinq versions distinctes sans copie. La suppression emporte aussi un fichier ajouté dans Fichiers ou une save modifiée depuis l’écriture du manifeste. La règle 1 exige une sauvegarde avant cette suppression. `CLAUDE.md:59` · `FileSaveVault.swift:181–200` · `FileSaveVault+Convergence.swift:279–286` · `VaultConvergenceTests.swift:145–178`
- **La rotation confond « téléchargée » et « restaurable ».** Un dossier dont `Game.sav` a été supprimé dans Fichiers, ou dont les octets ont changé, peut passer `isFullyLocal`. Avec dix versions récentes dont les fichiers sont absents ou non téléchargés, une ancienne version intacte peut être la seule restaurable. Si la nouvelle publication devient à son tour indisponible avant la rotation, celle-ci peut protéger un dossier incomplet et supprimer l’ancienne copie intacte. Le contrôle doit porter sur les fichiers attendus et leurs empreintes. Une erreur d’énumération est également traitée comme un dossier vide par `isFullyLocal`, ce qui invalide la protection contre les placeholders lors du rangement et de la rotation. `FileSaveVault.swift:192–200` · `FileSaveVault+Convergence.swift:305–331`
- **Un `rmdir` refusé peut laisser des versions sans identité.** Le retrait coordonné protège les versions présentes en faisant échouer `rmdir` si une entrée arrive entre-temps. En revanche, le code a déjà retiré `.game.json` ou `.console.json`. Il poursuit même si la lecture préalable du manifeste échoue, et ignore l’échec de sa remise en place. Un dossier qui reçoit une version dans cette fenêtre peut donc subsister avec ses octets et disparaître de l’index. `FileSaveVault+Convergence.swift:245–269` · `FileSaveVault.swift:234–251`

## À corriger

- **L’union peut rester périmée après une livraison iCloud ou un rangement concurrent.** `games()` recharge les jeux depuis les chemins de console en cache. `versions()` et `addVersion()` réutilisent aussi l’index des jeux. Si iCloud livre un dossier de console doublon après l’indexation, ses versions peuvent rester invisibles et sa séquence maximale peut être ignorée à la publication. L’export ne recharge que les jeux, et seulement quand la liste initiale de candidats est vide. Une copie identique corrompue encore indexée suffit donc à empêcher la recherche d’une bonne copie arrivée sous un nouveau chemin. `FileSaveVault.swift:59–73, 100–126, 160–164, 213–230`
- **À séquence et date égales, ranger un dossier peut changer la dernière version.** Le départage utilise `SaveVersion.id`, qui passe d’un chemin relatif complet à un nom de dossier quand une version rejoint le jeu canonique. Deux versions distinctes peuvent donc permuter après un simple déplacement. Cela peut changer la référence de la sync, les regroupements de versions identiques et le côté de la limite de rotation où tombe une version. Le cas `A@1, B@8, A@9` du tour 1 est corrigé avec un index à jour. Le départage doit aussi rester stable en cas d’égalité. `FileSaveVault.swift:315–350` · `SaveSync.swift:145–154`
- **L’export public peut rendre des octets non vérifiés.** Si aucun candidat ne passe les contrôles, `export` retourne quand même la première copie non vérifiée, éventuellement trouvée par son ancien nom de dossier. Le partage et la restauration iOS passent par `exportVerified`, qui rejette les mauvaises empreintes. La méthode publique `export` expose toujours une copie qui peut appartenir à une autre version. `FileSaveVault.swift:100–126` · `SaveVault.swift:199–212` · `AppModel+SaveSync.swift:165–176`
- **Le premier passage de rangement contourne les règles d’identité du §8.** Entre deux dossiers de console, un système entier peut être déplacé sous un nom libre sans que son identité soit connue. En cas de collision, le code déplace des jeux vers le système de même nom sans comparer les identités des systèmes. Un système dont le manifeste d’un jeu est illisible peut ainsi bouger, ou recevoir des jeux d’un autre système après un renommage manuel. Le tri ordinaire place désormais `Brick` avant `Arcade 2`, mais accepte aussi ` 0` et ` (0)` comme suffixes prioritaires. Je n’ai pas identifié de boucle interne. Un déplacement qui échoue durablement est retenté à chaque rechargement. `FileSaveVault+Convergence.swift:35–58, 87–124, 174–197` · `docs/specs/06-app-ios.md:164`
- **Un envoi peut rester en pause après une reconnexion réussie.** Le commit `3be178a9` déballe uniquement l’erreur API `disconnected`. Les autres erreurs restent propagées. Si le refus de l’ancienne connexion arrive après le balayage des envois en pause, la reprise dépend d’un seul `GET /device`. Si cette requête échoue transitoirement, par exemple avec un `500`, l’envoi reste en pause jusqu’à une autre action de reprise, même si la session courante est connectée. Le test ajouté couvre la reconnexion après l’enregistrement de la pause. `ConsoleSession.swift:212–220, 394–411, 463–472, 491–497` · `TransferQueue.swift:521–525` · `ClientAccessAppTests.swift:168–192`
